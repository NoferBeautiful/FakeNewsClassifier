## Задача

Разработать систему классификации фейковых новостей на основе DistilBERT. Система должна уметь обучать модели, делать предсказания, объяснять решения и работать в потоковом режиме.

## Датасет

FakeNewsNet с новостями из PolitiFact и GossipCop. Данные содержат текст новостей, метки (fake/real) и метаданные.

Качество данных

- Проверка на пропуски и дубликаты
- Анализ распределения классов
- Очистка текста от лишних символов/спецзнаков
- Разделение на train/test с сохранением баланса классов
- Сохранение отчетов о качестве данных в reports/

## Валидация

- Метрики: accuracy, precision, recall, F1
- Hold-out валидация (train/test split по времени)
- Сравнение с baseline моделью
- Сохранение метрик в metrics.json

## Сохранение артефактов

- Модель в формате safetensors
- Конфигурация модели в config.json
- Токенизатор в tokenizer.json
- Метрики в metrics.json
- Логи обучения в checkpoints/

## Модели

Базовая архитектура: DistilBERT с замороженным энкодером

Архитектура энкодера

- Предобученный DistilBERT (distilbert-base-uncased) как feature extractor
- 6 слоев трансформера, 768 скрытых размерностей, 12 attention heads
- Замороженные веса энкодера для стабильности (freeze_encoder=True)
- Максимальная длина последовательности: 512 токенов

Классификационная голова

- Dropout слой (p=0.2) для регуляризации
- Полносвязный слой 768 -> 2 (fake/real)
- Softmax активация для получения вероятностей

Гиперпараметры обучения

- Оптимизатор: AdamW с learning rate 2e-5
- Batch size: 32
- Количество эпох: 3
- Weight decay: 0.01
- Warmup steps: 500
- Early stopping с patience=3

Дополнительные модели

- baseline_frozen_encoder_trump - обучена на данных с упоминаниями Трампа
- baseline_frozen_encoder_tuned2018 - обучена на данных 2018 года

## Функционал

CLI команды через run.py

- train - обучение модели
- update - дообучение существующей модели
- validate - валидация на тестовых данных
- inference - пакетный инференс
- predict - предсказание одной новости
- explain - объяснение предсказания через attention
- summary - сводка по всем моделям
- compare - сравнение двух моделей

Интерпретируемость

- Визуализация attention weights для объяснения предсказаний
- Выделение токенов с наибольшим влиянием на решение
- Цветовая кодировка по важности токенов

## Потоковый режим

- Эмуляция потокового поступления данных
- Детекция дрейфа данных (по упоминаниям Трампа)
- Автоматическое переключение модели при дрейфе
- Отчеты в реальном времени с изменяемым интервалом
- Поддержка пустых запросов для эмуляции реального трафика

## CI/CD + HF

GitHub Actions workflow (.github/workflows/train.yml)

- Триггер: push или pull request в репозиторий
- Среда: ubuntu-latest с Python 3.10
- Шаги:
  - Checkout кода
  - Установка зависимостей из requirements.txt
  - Валидация модели baseline_frozen_encoder на тестовых данных
  - Загрузка результатов валидации как artifacts (metrics.json)
- Результат: проверка что существующая модель работает корректно
- Примечание: CLI также поддерживает обучение и дообучение моделей через команды `train` и `update`
